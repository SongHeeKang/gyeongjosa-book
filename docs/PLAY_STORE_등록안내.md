| 항목 | 규격 | 준비 상태 |

| 태블릿 스크린샷 | 선택 (안 넣어도 됨) | — |

스크린샷 추천 (5~6장, 각 장 위에 짧은 문구를 넣으면 좋아요):

1. 홈 — "주고받은 마음을 한눈에" (요약 · 일정 달력)
2. 행사 장부 작성 — "이름 적고 금액만 누르면 저장"
3. 사람 상세 — "사람별로 보낸 돈 · 받은 돈"
4. 일정 추가 알림 — "원하는 날짜 · 시간에 알려 드려요"
5. 공유하기 선택창 — "엑셀 · 텍스트로 보내기"

> 요즘 폰 화면을 그대로 캡처하면 세로가 너무 길어(예: 1440×3120, 2.17배) 거절돼요. 1080×1920 같은 9:16으로 잘라서 올리세요.
> 스크린샷에는 실제 사람 이름 · 전화번호가 보이지 않게, 예시 이름으로 넣은 데이터를 쓰세요.

## 3. Play Console 진행 순서 (자세히)

### 3-1. 앱 만들기

Play Console 첫 화면 > **앱 만들기**

| 칸 | 입력 |
|---|---|
| 앱 이름 | 경조사 장부 - 축의금 부의금 기록 |
| 기본 언어 | 한국어 – ko-KR |
| 앱 또는 게임 | 앱 |
| 무료 또는 유료 | **무료** (인앱 결제가 있어도 무료 앱) |
| 선언 | 개발자 프로그램 정책 · 미국 수출법 동의 체크 |

> 무료로 만든 앱은 나중에 유료로 바꿀 수 없어요. 무료 + 인앱 결제(프로 4,900원)가 맞아요.

### 3-2. 결제 프로필 (인앱 결제를 팔려면 필수)

설정 > **결제 프로필** — 판매자 정보 · 정산 계좌를 넣어 판매자 계정을 만들어요.
이게 없으면 3-6의 인앱 상품을 만들 수 없어요.

### 3-3. 앱 설정 (대시보드 > '앱 설정' 할 일 목록, 정책 > 앱 콘텐츠)

| 항목 | 답 |
|---|---|
| 개인정보처리방침 | `https://github.com/SongHeeKang/gyeongjosa-book/blob/main/PRIVACY.md` (공개 저장소라 열리는 것 확인함 · 2026-11-26. 문의 이메일을 먼저 채우세요) |
| 앱 액세스 권한 | "모든 기능을 별도 액세스 권한 없이 사용할 수 있음" (로그인 없음) |
| 광고 | "아니요, 앱에 광고가 없습니다" |
| 콘텐츠 등급 | 설문 시작 → 이메일 입력 → 카테고리 "기타 앱 유형(유틸리티 · 생산성 등)" → 폭력 · 성적 · 언어 · 도박 등 모두 "아니요", 사용자 간 소통 "아니요", 디지털 상품 구매 "예" → 보통 **전체이용가** |
| 타겟층 및 콘텐츠 | **만 18세 이상**만 선택 (어린이 대상 앱이 아니어야 심사가 단순해요) |
| 뉴스 앱 | 아니요 |
| 데이터 보안 | "앱이 필수 사용자 데이터 유형을 수집하거나 공유하나요?" → **아니요**. 기록은 폰에만 저장되고 서버로 보내지 않아요. 결제는 Google Play가 처리해요 |
| 광고 ID | "아니요" (광고 ID를 쓰지 않아요) |
| 정부 앱 | 아니요 |
| 금융 기능 | "앱에서 금융 기능을 제공하지 않음" (돈을 기록만 하고 송금 · 대출 등은 없음) |
| 건강 | 해당 없음 |

### 3-4. 스토어 설정 · 기본 스토어 등록정보

- **스토어 설정**: 앱 카테고리 **라이프스타일**(또는 금융), 태그 선택(가계부 · 생활), 연락처 이메일 **appmihk87@gmail.com** (스토어에 공개돼요), 웹사이트 · 전화는 비워도 돼요.
- **기본 스토어 등록정보**: 1장의 글(앱 이름 · 간단한 설명 · 자세한 설명)과 2장의 이미지(아이콘 · 그래픽 이미지 · 스크린샷)를 넣고 저장.

### 3-5. 내부 테스트로 첫 AAB 올리기

1. 테스트 및 출시 > 테스트 > **내부 테스트** > 새 버전 만들기
2. 처음 한 번 **Play 앱 서명** 사용에 동의 (Google이 최종 서명 키를 보관, 내 업로드 키는 업로드용)
3. AAB 파일(`build/app/outputs/bundle/release/app-release.aab`) 업로드
4. 출시 노트 붙여 넣기 → 저장 → 검토 → 내부 테스트 출시
5. 테스터 탭에서 이메일 목록 만들기(내 Gmail) → 참여 링크로 들어가 "테스터 되기" → 폰의 Play 스토어에서 설치

> 지금 폰에 깔린 APK(이 맥의 테스트 키)와 Play에서 받는 앱은 서명이 달라서, 처음 한 번은 기존 앱을 지우고 설치해야 해요. 지우기 전에 앱의 **설정 > 백업 파일 만들기**로 백업하세요.

### 3-6. 인앱 상품 만들기 (첫 AAB를 올린 뒤에 가능)

수익 창출 > 제품 > **일회성 제품(인앱 상품)** > 만들기

| 칸 | 입력 |
|---|---|
| 제품 ID | `pro_lifetime` (**나중에 바꿀 수 없음**, 앱 코드와 똑같아야 함) |
| 이름 | 경조사 장부 프로 (평생 이용권) |
| 설명 | 사람 무제한 · 내 행사 장부 무제한 · 관계별 · 연도별 통계 |
| 가격 | 4,900원 |

저장 후 **활성화**. 결제 테스트 순서는 `docs/PLAY_CONSOLE_결제설정.md` (라이선스 테스터 → 테스트 카드로 결제 → 앱 재설치 후 구매 복원 확인).

### 3-7. 비공개 테스트 (개인 개발자 계정은 필수)

2023년 11월 이후 만든 **개인** 개발자 계정은 프로덕션에 내기 전에:

- 테스트 > **비공개 테스트** 트랙에 같은 AAB를 올리고
- **테스터 12명 이상이 14일 동안 계속 참여**해야
- 대시보드 > **프로덕션 액세스 신청**을 할 수 있어요 (신청 때 테스트 내용 · 앱 설명 질문에 답함)

테스터는 Gmail 주소로 목록을 만들고 참여 링크를 보내 "테스터 되기"를 누르게 하면 돼요. 가족 · 지인에게 미리 부탁해 두세요.

### 3-8. 프로덕션 출시

1. 테스트 및 출시 > **프로덕션** > 국가/지역: 대한민국 추가
2. 새 버전 만들기 → 비공개 테스트에서 검증한 AAB 승격(또는 업로드) → 출시 노트
3. 검토 제출 → 보통 며칠 안에 심사 결과 메일

### 3-9. 다음 업데이트 때

- 버전 번호(versionCode)는 매번 올라가야 해요. (`version: 1.0.0+N`의 N)
- 같은 **업로드 키**로 서명한 AAB를 올려요.
- 출시 노트에 바뀐 점을 적어요.

## 4. 심사에서 자주 걸리는 것 (이 앱 기준 점검)

- ✅ 정확한 알람 권한 안 씀 (일반 예약 알림만)
- ✅ 연락처 읽기 권한 안 씀 (시스템 선택창만)
- ✅ 결제는 Google Play 결제만 (`in_app_purchase`)
- ✅ 광고 ID 안 씀, 광고 없음
- ✅ 대상 SDK 36
- ✅ 개인정보처리방침 URL 열림 (공개 저장소)
- ⚠ 개인정보처리방침 · 설정 [문의하기]의 문의 이메일이 채워졌는지
- ⚠ 스크린샷 비율(2배 이하), 개인정보가 보이지 않는지
